Why Single-Tool Approaches Miss IDE Extension Vulnerabilities

🏷
OSV: Name Mismatch
VS Code extensions use publisher-scoped names (e.g. ms-python.python) that don't correspond to npm package names. OSV.dev's npm ecosystem lookup fails to match them.
📦
OSV: Ecosystem Limitation
OSV.dev has no dedicated "vscode" or "jetbrains" ecosystem. Extensions/IDEs must be queried as npm packages, but most aren't published to npm.
🔍
Trivy: Different Layer
Trivy scans transitive dependencies bundled inside extensions (npm/NuGet packages), but misses extension-level and IDE-level CVEs tracked in NVD via CPE identifiers.
🧠
Trivy: No IDE Discovery
Trivy does not identify WebStorm, IntelliJ, or other IDEs as software components. It finds picomatch vulnerabilities in a plugin jar, but not the WebStorm IDE CVEs themselves.
🛡
Our Multi-Layer Approach
Supply Chain Scanner discovers extensions + IDEs, extracts metadata from package.json, and queries 4 intelligence sources — catching both extension-level and IDE-level CVEs that single-source tools miss.
🤝
Complementary Coverage
Trivy's dependency scanning + our extension/IDE scanning = more complete picture. Combining both tools covers both transitive dependency risks and top-level software CVEs.
